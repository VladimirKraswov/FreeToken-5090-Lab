# Qwen в Pi Code GUI: исчерпание ответа и ограниченное восстановление

> Update 2026-09-22: the installed profile now uses Medium for ordinary work and Low only for the bounded recovery. The Low measurements below describe the original incident fix. A later normal-stop incident was traced to FreeToken losing a tool call inside reasoning; see [the shared engine fix](QWEN_TOOL_HANDOFF.md). No additional normal-stop retry was added to Pi.

После успешного compaction при **tokensBefore=82324** следующий ответ завершился
с `stopReason="length"`: **24785 входных и 32768 выходных токенов**. В нём был
только thinking размером **110943 символа**, без вызова инструмента.
Это исчерпание лимита одного ответа; переполнения контекста, тайм-аута или
ошибки инструмента в этом событии не было.

Прежний recovery требовал `.pi/AUTONOMOUS`, отсутствующий в проекте. Кроме того,
он мог продолжать обычные завершения, повторять ошибки, а wrapper запускал Pi
заново без общего ограничения. `extensions=[]` само по себе не отключает
автоматическое обнаружение глобальных расширений Pi.

## Рекомендованный профиль для этого случая

- **Thinking: Low** в Pi и Pi Code GUI; применяется также при загрузке сохранённой
  Qwen-сессии и выборе этой модели. После этого уровень можно изменить вручную.
- **maxTokens: 16384**, общий контекст модели **131072**.
- **TypeScript runtime** Pi Code GUI. Rust runtime TypeScript-расширение не загружает.
- Провайдер/модель: `local-qwen/qwen38-flash-next`.

16384 - [документированный стандарт Pi для пользовательских моделей](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/models.md#model-configuration),
а не доказанный оптимум качества Qwen. Low выбран для коротких рабочих шагов по
результатам этого сбоя. Большие отдельные бюджеты reasoning и ответа из
[карточки Qwen](https://huggingface.co/Qwen/Qwen3.8-Flash-Next#best-practices)
описаны для конфигурации с 1M контекста и не переносятся напрямую на наш сервер.

Замеры скорости в основном отчёте сделаны с **Medium**. Этот клиентский профиль
не подменяет их и не требует изменения настроек работающего FreeToken.

## Как работает исправление

1. После окончательного `length` автоматически отправляется **одно короткое
   продолжение на пользовательское задание**: восстановить `.pi/TASK.md`,
   проверить Git, вызвать инструмент в первые 300 слов.
2. При usage **>=60000** сначала выполняется compaction. Продолжение разрешено
   только после успеха. Уже выполненное Pi сжатие учитывается.
3. Бюджет резервируется в служебной записи сессии **до** асинхронных действий.
   Перезагрузка, повторное событие и сам recovery-запрос не обнуляют защиту.
4. Если продолжение тоже упирается в лимит, агент остаётся остановлен.
   Новое пользовательское сообщение может разрешить новое однократное восстановление.
5. После `aborted/error`, `DONE/NEEDS_INPUT`, при ожидающем пользовательском
   сообщении или ошибке compaction автоматического продолжения нет.
6. Безусловный перезапуск wrapper удалён. Расширение не создаёт и не изменяет
   файлы маркеров в рабочих проектах.

Правило первых 300 слов - инструкция модели, а не жёсткий перехват её потока.
Жёстко ограничено количество автоматических продолжений. Это защита от
конкретного отказа, а не гарантия завершения любой задачи без участия человека.

## Проверки и применение

**33 теста прошли**: события и защита от повторов, реальный Pi SDK с тестовым
OpenAI API, compaction, вызовы чтения/Git и коды завершения wrapper.
На живой Qwen: **Low, maxTokens16384, инструмент после 12 слов**, чтение
checkpoint и Git, финальный `READY`, `stopReason="stop"`.

[Код, примеры конфигурации и полная инструкция установки](../../integrations/pi/README.md).
[Обезличенные метаданные проверки](../../integrations/pi/evidence/verification.json).

Новые TypeScript-сессии загружают исправление при запуске. Для уже открытого
диалога дождитесь остановки текущей работы и выполните **PiGui: Reload Context
Files**; эта команда перезагружает и расширения. Можно также перезагрузить окно
VS Code. Удалять историю или пересоздавать рабочий проект не требуется.
