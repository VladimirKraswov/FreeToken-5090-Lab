# Qwen Flash Next: выбор и настройка coding-agent

Этот отчёт фиксирует агентные испытания 22 сентября при окне 131072. Текущее
окно одиночного сервера RTX 5090 и новые замеры приведены в
[отчёте по контексту](context-tuning-20260927.md); прежние числа ниже не являются
описанием текущей серверной конфигурации.

Измерения от 22 сентября 2026. Основная локальная связка: **OpenCode 1.18.18 +
FreeToken-5090-Lab + RadixArk/Qwen3.8-Flash-Next-NVFP4**, обычное усилие Medium.
Pi / Pi Code GUI остаются доступными с теми же guardrails и исправленным исполнением
команд. DeepSeek Harness сохраняет свои сессии и поддержку этой модели.

Это практический выбор по небольшому локальному набору задач и возможностям
оболочки. Он не доказывает превосходство на любых проектах или равенство облачным
frontier-моделям. Ранее измеренная скорость decode не подменяет качество кода.

## Сравнение на одной модели

Последовательные запуски на одном GPU, один случайный прогон каждого сочетания.
Два новых Git-репозитория: асинхронный Python-кэш и история жестов JavaScript.
По восемь независимых acceptance checks, исходные тесты и несохранённая в Git
пользовательская заметка должны оставаться неизменными. Реальные проекты не
использовались как тестовые мишени. PASS требует завершения агента, прохождения
независимых и его собственных тестов, сохранности исходных файлов.

| Оболочка | Async cache | Gesture history |
|---|---|---|
| OpenCode 1.18.18 | PASS; 8/8; 372.2 с | PASS; 8/8; 193.3 с |
| Pi 0.85.1 | FAIL; 8/8; 600.0 с | PASS; 8/8; 180.2 с |
| DeepSeek Harness 0.1.1-rc.2 | PASS; 8/8; 625.3 с | PASS; 8/8; 580.9 с |
| Qwen Code 0.24.3 | FAIL; 2/8; 602.3 с | PASS; 8/8; 353.7 с |

Pi исправил код кэша (8/8), но завис на написанном им самим тесте с незавершаемым
ожиданием. Поэтому общий результат FAIL. У Qwen Code в кэш-задаче на момент
остановки были добавлены тесты, но исправление реализации не было закончено.
OpenCode после тайм-аута проверки старой реализации смог восстановиться и
завершить задачу. DSH cache занял 625 с: проверки пройдены, но строгий бюджет
600 с он превысил. Native deadline Pi/Qwen — 600 с, общий внешний cap — 630 с.
Различия собственного исполнения команд и системных промптов входят в сравнение.

Первый старт OpenCode с ошибочным унаследованным PWD исключён: были только
операции чтения. Runner исправлен через PWD и --dir. Ошибка инициализации SDK Pi
исправлена до обращения к модели. Это ошибки тестовой настройки, не результаты
качества. Исключённые сырые журналы не публикуются.

основных запросов: length на коротком title не означает отказ рабочего шага.

## Почему выбран OpenCode

Он завершил обе базовые задачи и хорошо подходит для обычной работы с репозиторием:
нативные инструменты файлов/Git/команд, LSP, локальный провайдер, сжатие контекста,
навыки по запросу, web UI и терминальный интерфейс. Результат истории у Pi близок
по времени; это не основание объявлять модель в Pi хуже. Выявленный Pi-сбой
исправлен на уровне выполнения инструмента.

[Qwen Code](https://github.com/QwenLM/qwen-code) поддерживает локальные модели,
но на этом наборе не дал причины переносить в него основную работу.
[Карточка Qwen](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) использует разные
harness в своих оценках, включая mini-SWE-agent; это не готовый рейтинг для
локальной NVFP4-версии. mini-SWE-agent здесь не устанавливался и не измерялся.
[Документация Claude Code](https://code.claude.com/docs/en/llm-gateway) не обещает
поддержку non-Claude моделей через gateway; существующая облачная конфигурация
сохранена, адаптер совместимости для неё не назначен основным вариантом.

## Исправления общей причины

1. Сохранён предыдущий [консервативный tool handoff](QWEN_TOOL_HANDOFF.md):
   завершённый корректный вызов известного инструмента при потерянной границе
   thinking восстанавливается в сервере; частичный/цитируемый/length-вызов не
   исполняется. Это исправление доступно всем клиентам API.
2. Исправлена [передача reasoning effort](AGENT_REASONING.md). Сочетание
   top-level Medium и enable_thinking=true больше не теряет выбранное усилие.
   Раньше шаблон Qwen в этом случае выбирал свой xhigh по умолчанию.
   Явное выключение thinking, свой effort и adaptive сохраняют приоритет.
3. В Pi foreground bash теперь имеет стандартный deadline 120 с. Явное большее
   значение допускается для долгих сборок. Нативный инструмент завершает только
   своё дерево процессов и возвращает ошибку модели. Зависший тест не считается
   успешным. Это обязанность оболочки, а не CUDA-движка.
4. Pi launcher проверяет выбранную модель, вместо старых адресов Qwen/Gemma;
   autonomous wrapper больше не отключает другие расширения и guardrails.
5. Финальный запуск полного OpenCode выявил второй системный блок после
   инъекции guardrails: шаблон Qwen возвращал HTTP 400 до начала генерации.
   Hook теперь сохраняет ссылку на массив и объединяет инструкции в одно
   начальное system message. Реальный сериализатор OpenCode проверен через
   локальный тестовый API: до исправления два system, после — один.
6. OpenCode progress reminder не блокирует инструменты и не требует от read-only
   reviewer запрещённого ему todowrite. Сжатие контекста также не навязывает
   создание плана там, где его не было.

Новые изменения движка относятся к обработке протокола, а не к GPU-ядрам.
Контекст 131072, Vision, BF16 KV, MTP=3, Triton, hybrid offload, CPU12,
prefill14336 и лимит 500 Вт сохранены. Веса и правила принятия MTP draft не менялись.
Дополнительное ускорение tok/s этой работой не заявляется; прежние измерения
на 100K+ коде см. в [аудите производительности](audit-results.md).

## Окончательная конфигурация

- Обычное рассуждение Medium, output cap 16384, серверный контекст 131072.
  16384 — документированный default Pi для custom models, а не доказанный
  глобальный оптимум Qwen. Для агента оставлен запас под ответы и tool output;
  native compaction может срабатывать раньше серверного предела.
- Один активный запрос GPU. Опциональная проверка qwen-review выполняется
  последовательно. Нет автоматического переключения на облачную модель.
- Общий компактный QWEN_FLASH_NEXT_GUARDRAILS.md загружается перед запросами
  Pi CLI, TypeScript Pi Code GUI, OpenCode и DeepSeek Harness, включая продолжение
  после compaction. Он не заменяет инструкции проекта и не наращивается логами.
- Три навыка: диагностика регрессии, проверка изменения, проверка web UI.
  repo_inspect читает Git и метаданные тестов; не исполняет package scripts.
  OpenCode использует LSP, Pi GUI — диагностику VS Code, когда она доступна.
  Браузерный сценарий выполняется в отдельной сессии, без личных cookies.
- Pi после length разрешает ровно одно продолжение в Low и затем возвращает
  Medium. При usage >=60000 сначала compaction. После error/aborted,
  DONE/NEEDS_INPUT, повторного length или ожидающего сообщения продолжения нет.
  Правило «инструмент в первые 300 слов» — инструкция, не гарантия модели.

Для установленной macOS-связки создан ярлык **Qwen OpenCode.app**. Он запускает
выделенный сервер только на `127.0.0.1:4096` и открывает web UI; повторный запуск
переиспользует его. В интерфейсе выбирается папка проекта. CLI: `opencode-qwen`
из папки проекта. Старые сессии, другие провайдеры и рабочие проекты сохранены.
Новые Pi GUI сессии загружают изменения; для уже открытой idle-сессии —
**PiGui: Reload Context Files**.

## Проверки реализации

- FreeToken: 668 server/regression tests; исходная минимальная регрессия падала
  на старом коде. Настоящий checkpoint tokenizer проверен для Low/Medium/xhigh.
- Pi: 39 Node-тестов, включая настоящий SDK с управляемым API, тайм-аут native
  bash, compaction, duplicate guard, terminal markers и однократную инъекцию
  guardrails; ещё 3 Python-проверки выбранного endpoint.
- OpenCode plugins: 3 проверки сохранения инструментов read-only reviewer и
  корректной валидации Todo и единственного system message. Полный настроенный
  профиль прошёл отдельный финальный запуск: **8/8 acceptance, 247.549 с**,
  repo_inspect и skill действительно использовались. Этот запуск не подменяет
  базовое сравнение. Предшествующий HTTP 400 сохранён как opencode-final.
- Реальный web UI: repo_inspect -> READY, 24 с, модель и qwen-build подтверждены.
- Живой Pi: Medium, tool после 10 слов, READY, 14.616 с, ошибок нет.
- После перезапуска движка: retrieval **105077 токенов** за 42.318 с, Vision
  2048x2048, tools и Responses API прошли. Это время всего retrieval-запроса,
  а не новая оценка TTFT или устойчивой скорости decode.

Финальные live-результаты и состояние развёртывания: [evidence](../../integrations/qwen-stack/evidence/).
Никакой небольшой набор тестов не доказывает полную автономность. Следующая
проверка качества должна быть на репрезентативных задачах конкретного проекта
с объективными acceptance checks, а не на увеличении объёма системного промпта.
