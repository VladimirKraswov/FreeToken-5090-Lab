# FreeToken 5090 Lab

Настроенный и проверенный форк **FreeToken-Kai** для
**RadixArk/Qwen3.8-Flash-Next-NVFP4** на одной **RTX 5090 32 GB**,
двух Xeon E5-2698 v4 и PCIe Gen3 x16. Здесь собраны изменения движка,
описание оборудования, конфигурация VM, исходные метрики и воспроизводимые тесты.

**Сохранены:** контекст 131072, BF16 KV, Vision, инструменты и OpenAI-compatible API.
Профиль рассчитан на один активный запрос. Веса основной модели не переквантованы.
Это Flash Next MoE, а не прежняя плотная Qwen 27B.

## Измеренный результат

В завершённой основной серии на реальном запросе с исходным кодом на 104868
входных токенов: **41,45 токена/с при temperature=0** и **38,06 при temperature=1**,
TTFT **40–41 с**. На синтетическом запросе с 105068 токенами: **49,23 токена/с**.
Это скорость выдачи после первого токена, включая reasoning; полная задержка
реального запроса с 1024 выходными токенами — около **66–67 с**.

Результаты дополнительного аудита и финальное подтверждение собраны в
[итоговой таблице](docs/rtx5090/audit-results.md). Небольшие различия между
повторами не выдаются за гарантированное ускорение. Заявление относится к
лучшему **проверенному** профилю, а не к доказанному глобальному максимуму.

## Изменения

1. Убрано копирование всей истории на каждом MTP-rollback: PLE читает только
   нужные последние токены.
2. Временные тензоры MTP и PLE освобождаются до следующих пиков расхода VRAM.
3. Интегрирован fused PLE hash из PR #338 с сохранением авторства **dejay2**.
4. Исправлено время жизни буферов этого патча: вытеснение обычного кэша форм
   больше не освобождает адреса, которые читает CUDA-граф.
5. Убрана лишняя CPU/GPU-синхронизация при очистке prefill-буферов MoE.
6. Добавлены регрессионные проверки, точная фиксация окружения и клиентских метрик.

Целевая CPU/GPU-серия: **135 passed, 4 skipped**. Пропуски и существующая
чувствительность одного CPU-теста к многопоточному BLAS описаны в отчёте;
неудачные эксперименты и исходные журналы сохранены.
